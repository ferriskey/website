# 密码策略

每个域都有自己的密码策略，单独存储，不与其他域设置一起保存，并在独立的界面上进行编辑。其在所有设置密码的场景中都会被执行：注册、管理员重置、用户通过电子邮件收到的重置链接、必需操作要求的更新以及用户自行更改密码。

## 规则

从未保存过策略的域使用以下默认值。它们遵循 [CNIL deliberation 2022-100](https://www.legifrance.gouv.fr/jorf/id/JORFTEXT000046444507)：至少 12 个字符，包含所有四种字符类型，且熵不低于 80 位。

| 字段 | 默认 | 说明 |
|---|---|---|
| `min_length` | `12` | 最小长度。API 接受 1 到 128 个字符 |
| `require_uppercase` | `true` | 至少一个大写字母 |
| `require_lowercase` | `true` | 至少一个小写字母 |
| `require_number` | `true` | 至少一个数字 |
| `require_special` | `true` | 至少包含一个既不是字母也不是数字的字符 |
| `max_age_days` | 无 | 已存储并返回，但未应用。请参阅 [Expiry is stored, not applied](#expiry-is-stored-not-applied) |
| `min_entropy_bits` | `80` | 拒绝低于此估算熵的密码。`0` 会禁用此检查，API 接受 0 到 256 |
| `forbid_common` | `true` | 拒绝在内置 100 个常用密码列表中的密码，或等于用户名或邮箱地址中 `@` 前的部分 |
| `check_breached` | `false` | 已存储，但 0.10.0 不进行违规检查，因此开启不会改变任何情况 |

`PUT` 取这些字段的任何子集，并保持其他字段不变。

当密码违反策略时，响应是一个 `422`，它一次列出所有违反的规则，每条规则一条条目，带有稳定的 `code`:

```json title="PUT /realms/{realm_name}/users/{user_id}/reset-password"
{
  "errors": [
    { "field": "password", "code": "too_short", "message": "Password is too short: 10 characters (minimum 12 required)" },
    { "field": "password", "code": "missing_uppercase", "message": "Password must contain at least one uppercase letter" },
    { "field": "password", "code": "missing_special", "message": "Password must contain at least one special character" },
    { "field": "password", "code": "insufficient_entropy", "message": "Password is not strong enough. Make it longer, or mix uppercase and lowercase letters, numbers and symbols" }
  ]
}
```

其他代码是 `missing_lowercase`、`missing_number` 和 `common_password`。匹配 `code`，不匹配 `message`；参见 [API 错误](/zh-CN/discover/guides/api-errors)。

<span id="entropy-is-the-rule-that-does-the-real-work" />

## 熵是完成实际工作的规则

四个字符类别要求是大家熟知的，也同样是最弱的。`Passw0rd!` 满足每一项要求。使用默认设置时，它会被另外两个规则拒绝：它有 9 个字符，且估计熵约为 59 比特。

FerrisKey 将熵估算为长度乘以字符集的二进制对数。字符集为密码使用的每种类别增加数量：小写字母 26 个，大写字母 26 个，数字 10 个，符号 33 个。这样默认的 80 比特要求比 12 个字符所暗示的严格：12 个字符来自所有四个类别得分 78.8 比特，因此使用默认设置密码需要 13 个字符。

有两点可以得出：

- 如果你提高熵值，你可以放宽字符类别的限制。仅使用小写字母时，18个字符可以达到80位，而17个字符则达不到（79.9）。一个较长的密码短语可以达到标准，并且不包含符号。要求使用符号会让用户倾向于使用 `Password1!`，而不是选择强密码。
- 该估算只计算ASCII字符，并以字节为单位计算长度。例如，仅由非ASCII字符组成的密码，比如中文，熵值为0位，并且不能通过大于0的任何熵值阈值。

`forbid_common` 是一项严格的检查。它将整个密码（不区分大小写）与一个包含100条条目的列表以及用户名和电子邮件的本地部分进行比较。`password1` 在列表中，而 `Password1!` 不在列表中。

<span id="expiry-is-stored-not-applied" />

## 过期信息被存储，但不会应用

`max_age_days` 在设置之前会显示为 `null`，API 接受 0 或更多。控制台显示为密码过期，并描述在那么多天之后强制更改，但 0.10.0 的登录路径中没有任何地方读取该值。密码不会因为年龄而过期。

要让某人更改密码，请使用 `temporary: true` 重置它。用户将在下一次登录时被引导到 `update_password` 所需操作。参见 [用户](/zh-CN/discover/core-concepts/users#administering-a-user)。

<span id="the-public-endpoint" />

## 公共端点

```
GET /realms/{realm_name}/password-policy/public
```

未认证，并且返回五个字段：`min_length`、`require_uppercase`、`require_lowercase`、`require_number` 和 `require_special`。熵、常见密码和泄露设置不属于其中的一部分，因此表单可以在字段旁列出字符规则，但只能在提交后通过 `422` 了解其他内容。

这可以让注册或重置表单显示规则，而不是在往返后拒绝用户。请使用它，而不是在前端硬编码规则：身份域的策略可能会改变，而检查过期副本的表单会告诉用户他们的密码没问题，然后看着服务器拒绝它。

<span id="api-reference" />

## API参考

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/realms/{realm_name}/password-policy` | 阅读完整策略 |
| `PUT` | `/realms/{realm_name}/password-policy` | 更新策略 |
| `GET` | `/realms/{realm_name}/password-policy/public` | 读取五条公共规则，未认证 |

**所需权限:** `manage_realm`，包括读取和更新权限。公共端点不需要任何权限。

<Callout variant="info" title="更改策略不会使现有密码失效">

更严格的策略适用于每个用户下一次设置的密码。已存储的密码仍然可用，并且不会扫描它们以对照新规则。

</Callout>

<span id="imported-passwords" />

## 导入的密码

从另一个IAM迁移的密码是一种特殊情况。FerrisKey在导入时接受哈希并将其保留为用户的密码凭据。用户第一次成功登录时，它会使用argon2id重新哈希密码：明文密码只有在那一刻才可用。

该策略不适用于导入的密码，因为FerrisKey从未看到明文密码。它在该用户下次更改密码时才会生效。当管理员调用导入端点时，导入会在[SeaWatch](/zh-CN/modules/seawatch/event-types)中触发一个`password_imported`事件。首次登录时的升级不会触发任何事件。参见[导出与导入](/zh-CN/discover/guides/portability#password-hashes)。
