<span id="credentials" />

# 凭据

<Callout variant="info" title="从其他身份与访问管理系统迁移？">

可以按用户导入来自其他身份提供商的密码哈希，并在首次登录时重新编码为argon2id。参见 [导出与导入](/zh-CN/discover/guides/portability#password-hashes)。

</Callout>

凭据是身份的证明。一个用户可以同时拥有多个凭据，这使得多因素认证成为可能。

<span id="credential-types" />

## 凭据类型

<span id="password" />

### 密码

密码使用Argon2id进行哈希，这是一个内存硬化算法，选择它是因为它使基于GPU的暴力破解代价高昂。

存储的数据：
- `hash_iterations`。Argon2迭代次数
- `algorithm`。哈希算法标识符
- `salt`。每个凭据的唯一随机盐

密码从不以明文形式存储，也无法被检索，只能进行验证。

新哈希的成本在服务器上设定，通过[配置指南](/zh-CN/discover/guides/configuration)中描述的三个变量：

| 变量 | 默认 | 它设置的内容 |
|---|---|---|
| `PASSWORD_HASH_MEMORY_KIB` | `7168` | 每个哈希使用的内存（以 KiB 为单位） |
| `PASSWORD_HASH_ITERATIONS` | `5` | 迭代次数 |
| `PASSWORD_HASH_PARALLELISM` | `1` | 并行度 |

验证从存储的哈希中读取成本，因此更改这些值只会影响新的哈希。在下一次成功登录时，使用其他成本或其他算法（如 bcrypt）的密码哈希会使用当前设置重新进行哈希。

### TOTP

与 Google Authenticator、Authy 或 1Password 等认证器应用配对的共享密钥。每个认证器的注册方式相同：HMAC-SHA1、6位数字、30 秒步长。注册二维码包含这些值，因此应用无需设置。FerrisKey 接受前一步、当前及下一步的代码，从而可以吸收一些时钟漂移。用户一次持有一个认证器，注册新的认证器会替换旧的。

种子存储在数据库中。只有在设置 `SECRETS_ENCRYPTION_KEYS` 时才会被封存；没有密钥时，它以明文存储。参见 [静态密钥](/zh-CN/discover/guides/secrets-at-rest)。

TOTP 凭据由 [Trident](/zh-CN/modules/trident/overview) 模块管理。

<span id="webauthn-passkeys" />

### WebAuthn 通行密钥

硬件安全密钥和平台认证器：Touch ID、Windows Hello、Android生物识别。FerrisKey 存储公钥和凭据元数据。私钥永远不会离开用户设备。

<span id="recovery-codes" />

### 恢复码

备用代码每个只能使用一次，替代正常的多因素认证（MFA）挑战。FerrisKey 在设置 MFA 时不会创建这些代码。已登录的用户可以请求一组备用代码：

```
POST /realms/{realm_name}/login-actions/generate-recovery-codes
```

请求体包含 `elevation_id`、`amount` 中代码的数量，以及 `code_format`，其中 `b32-split-4` 是唯一值。权限提升必须通过重新使用密码进行身份认证，因此被盗会话不能自行生成代码；如果没有身份认证，请求将以 `403` 失败。详见 [账户安全](/zh-CN/modules/account/security)。

明文代码只会返回一次。它们在存储之前会像其他密钥一样进行哈希处理。生成新的一组会使之前的代码失效。[恢复代码](/zh-CN/modules/trident/recovery-codes)介绍了它们的使用方法。

<span id="federated" />

### 联合

凭据模型有一种变体记录，它指向外部身份提供者，而不是保存密钥，携带 `provider_id` 和 `provider_type`。在 0.10.0 中没有创建该记录的操作。从 LDAP 提供者引入的用户会获得一个 `password` 凭据，其存储的密钥为字面值 `federated`，这告知登录流程应检查密码与目录而非数据库匹配。通过例如 GitHub 的代理提供者登录的用户根本没有凭据：账户通过链接行与提供者关联。提供者通过 [Abyss](/zh-CN/modules/abyss/overview) 模块进行管理。

<span id="temporary-credentials" />

## 临时凭据

凭据可以被标记为临时。这几乎总是密码，并且会触发 `update_password` 所需的操作：用户必须在获得完整访问权限之前设置一个永久密码。

<span id="credential-lifecycle" />

## 凭据生命周期

用户通常最终会拥有一个密码，一旦设置了 MFA 就会有一个 TOTP 凭据，如果他们请求过的话，还会有一组恢复码，以及可能一个或多个 WebAuthn 密钥。

管理员可以通过管理控制台重置密码并删除任何凭据。用户通过账户控制台管理自己的凭据，该控制台在进行敏感更改之前会要求他们重新进行身份认证。
