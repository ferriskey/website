# 密碼策略

每個域都有自己的密碼策略，單獨儲存，不與其他域設定一起儲存，並在獨立的介面上進行編輯。其在所有設定密碼的場景中都會被執行：註冊、管理員重置、使用者透過電子郵件收到的重置連結、必需操作要求的更新以及使用者自行更改密碼。

## 規則

從未儲存過策略的域使用以下預設值。它們遵循 [CNIL deliberation 2022-100](https://www.legifrance.gouv.fr/jorf/id/JORFTEXT000046444507)：至少 12 個字元，包含所有四種字元型別，且熵不低於 80 位。

| 欄位 | 預設 | 說明 |
|---|---|---|
| `min_length` | `12` | 最小長度。API 接受 1 到 128 個字元 |
| `require_uppercase` | `true` | 至少一個大寫字母 |
| `require_lowercase` | `true` | 至少一個小寫字母 |
| `require_number` | `true` | 至少一個數字 |
| `require_special` | `true` | 至少包含一個既不是字母也不是數字的字元 |
| `max_age_days` | 無 | 已儲存並返回，但未應用。請參閱 [Expiry is stored, not applied](#expiry-is-stored-not-applied) |
| `min_entropy_bits` | `80` | 拒絕低於此估算熵的密碼。`0` 會禁用此檢查，API 接受 0 到 256 |
| `forbid_common` | `true` | 拒絕在內建 100 個常用密碼列表中的密碼，或等於使用者名稱或郵箱地址中 `@` 前的部分 |
| `check_breached` | `false` | 已儲存，但 0.10.0 不進行違規檢查，因此開啟不會改變任何情況 |

`PUT` 取這些欄位的任何子集，並保持其他欄位不變。

當密碼違反策略時，響應是一個 `422`，它一次列出所有違反的規則，每條規則一條條目，帶有穩定的 `code`:

```json title="PUT /realms/{realm_name}/users/{user_id}/reset-password"
{
  "errors": [
    { "field": "password", "code": "too_short", "message": "Password is too short: 10 characters (minimum 12 required)" },
    { "field": "password", "code": "missing_uppercase", "message": "Password must contain at least one uppercase letter" },
    { "field": "password", "code": "missing_special", "message": "Password must contain at least one special character" },
    { "field": "password", "code": "insufficient_entropy", "message": "Password is not strong enough. Make it longer, or mix uppercase and lowercase letters, numbers and symbols" }
  ]
}
```

其他程式碼是 `missing_lowercase`、`missing_number` 和 `common_password`。匹配 `code`，不匹配 `message`；參見 [API 錯誤](/zh-TW/discover/guides/api-errors)。

<span id="entropy-is-the-rule-that-does-the-real-work" />

## 熵是完成實際工作的規則

四個字元類別要求是大家熟知的，也同樣是最弱的。`Passw0rd!` 滿足每一項要求。使用預設設定時，它會被另外兩個規則拒絕：它有 9 個字元，且估計熵約為 59 位元。

FerrisKey 將熵估算為長度乘以字符集的二進位制對數。字符集為密碼使用的每種類別增加數量：小寫字母 26 個，大寫字母 26 個，數字 10 個，符號 33 個。這樣預設的 80 位元要求比 12 個字元所暗示的嚴格：12 個字元來自所有四個類別得分 78.8 位元，因此使用預設設定密碼需要 13 個字元。

有兩點可以得出：

- 如果你提高熵值，你可以放寬字元類別的限制。僅使用小寫字母時，18個字元可以達到80位，而17個字元則達不到（79.9）。一個較長的密碼短語可以達到標準，並且不包含符號。要求使用符號會讓使用者傾向於使用 `Password1!`，而不是選擇強密碼。
- 該估算只計算ASCII字元，並以位元組為單位計算長度。例如，僅由非ASCII字元組成的密碼，比如中文，熵值為0位，並且不能透過大於0的任何熵值閾值。

`forbid_common` 是一項嚴格的檢查。它將整個密碼（不區分大小寫）與一個包含100條條目的列表以及使用者名稱和電子郵件的本地部分進行比較。`password1` 在列表中，而 `Password1!` 不在列表中。

## 過期資訊被儲存，但不會應用

`max_age_days` 在設定之前會顯示為 `null`，API 接受 0 或更多。控制檯顯示為密碼過期，並描述在那麼多天之後強制更改，但 0.10.0 的登入路徑中沒有任何地方讀取該值。密碼不會因為年齡而過期。

要讓某人更改密碼，請使用 `temporary: true` 重置它。使用者將在下一次登入時被引導到 `update_password` 所需操作。參見 [使用者](/zh-TW/discover/core-concepts/users#administering-a-user)。

<span id="the-public-endpoint" />

## 公共端點

```
GET /realms/{realm_name}/password-policy/public
```

未認證，並且返回五個欄位：`min_length`、`require_uppercase`、`require_lowercase`、`require_number` 和 `require_special`。熵、常見密碼和洩露設定不屬於其中的一部分，因此表單可以在欄位旁列出字元規則，但只能在提交後透過 `422` 瞭解其他內容。

這可以讓註冊或重置表單顯示規則，而不是在往返後拒絕使用者。請使用它，而不是在前端硬編碼規則：身分域的策略可能會改變，而檢查過期副本的表單會告訴使用者他們的密碼沒問題，然後看著伺服器拒絕它。

<span id="api-reference" />

## API參考

| 方法 | 路徑 | 說明 |
|---|---|---|
| `GET` | `/realms/{realm_name}/password-policy` | 閱讀完整策略 |
| `PUT` | `/realms/{realm_name}/password-policy` | 更新策略 |
| `GET` | `/realms/{realm_name}/password-policy/public` | 讀取五條公共規則，未認證 |

**所需權限:** `manage_realm`，包括讀取和更新權限。公共端點不需要任何權限。

<Callout variant="info" title="更改策略不會使現有密碼失效">

更嚴格的策略適用於每個使用者下一次設定的密碼。已儲存的密碼仍然可用，並且不會掃描它們以對照新規則。

</Callout>

## 匯入的密碼

從另一個IAM遷移的密碼是一種特殊情況。FerrisKey在匯入時接受雜湊並將其保留為使用者的密碼憑據。使用者第一次成功登入時，它會使用argon2id重新雜湊密碼：明文密碼只有在那一刻才可用。

該策略不適用於匯入的密碼，因為FerrisKey從未看到明文密碼。它在該使用者下次更改密碼時才會生效。當管理員呼叫匯入端點時，匯入會在[SeaWatch](/zh-TW/modules/seawatch/event-types)中觸發一個`password_imported`事件。首次登入時的升級不會觸發任何事件。參見[匯出與匯入](/zh-TW/discover/guides/portability#password-hashes)。
