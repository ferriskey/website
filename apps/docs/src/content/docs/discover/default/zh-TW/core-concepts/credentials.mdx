# 憑據

<Callout variant="info" title="從其他身分與存取管理系統遷移？">

可以按使用者匯入來自其他身分提供商的密碼雜湊，並在首次登入時重新編碼為argon2id。參見 [匯出與匯入](/zh-TW/discover/guides/portability#password-hashes)。

</Callout>

憑據是身分的證明。一個使用者可以同時擁有多個憑據，這使得多因素認證成為可能。

<span id="credential-types" />

## 憑據型別

<span id="password" />

### 密碼

密碼使用Argon2id進行雜湊，這是一個記憶體硬化演算法，選擇它是因為它使基於GPU的暴力破解代價高昂。

儲存的資料：
- `hash_iterations`。Argon2迭代次數
- `algorithm`。雜湊演算法識別符號
- `salt`。每個憑據的唯一隨機鹽

密碼從不以明文形式儲存，也無法被檢索，只能進行驗證。

新雜湊的成本在伺服器上設定，透過[配置指南](/zh-TW/discover/guides/configuration)中描述的三個變數：

| 變數 | 預設 | 它設定的內容 |
|---|---|---|
| `PASSWORD_HASH_MEMORY_KIB` | `7168` | 每個雜湊使用的記憶體（以 KiB 為單位） |
| `PASSWORD_HASH_ITERATIONS` | `5` | 迭代次數 |
| `PASSWORD_HASH_PARALLELISM` | `1` | 並行度 |

驗證從儲存的雜湊中讀取成本，因此更改這些值只會影響新的雜湊。在下一次成功登入時，使用其他成本或其他演算法（如 bcrypt）的密碼雜湊會使用當前設定重新進行雜湊。

### TOTP

與 Google Authenticator、Authy 或 1Password 等認證器應用配對的共享金鑰。每個認證器的註冊方式相同：HMAC-SHA1、6位數字、30 秒步長。註冊二維碼包含這些值，因此應用無需設定。FerrisKey 接受前一步、當前及下一步的程式碼，從而可以吸收一些時鐘漂移。使用者一次持有一個認證器，註冊新的認證器會替換舊的。

種子儲存在資料庫中。只有在設定 `SECRETS_ENCRYPTION_KEYS` 時才會被封存；沒有金鑰時，它以明文儲存。參見 [靜態金鑰](/zh-TW/discover/guides/secrets-at-rest)。

TOTP 憑據由 [Trident](/zh-TW/modules/trident/overview) 模組管理。

<span id="webauthn-passkeys" />

### WebAuthn 通行金鑰

硬體安全金鑰和平臺認證器：Touch ID、Windows Hello、Android生物識別。FerrisKey 儲存公鑰和憑據後設資料。私鑰永遠不會離開使用者裝置。

<span id="recovery-codes" />

### 恢復碼

備用程式碼每個只能使用一次，替代正常的多因素認證（MFA）挑戰。FerrisKey 在設定 MFA 時不會建立這些程式碼。已登入的使用者可以請求一組備用程式碼：

```
POST /realms/{realm_name}/login-actions/generate-recovery-codes
```

請求體包含 `elevation_id`、`amount` 中程式碼的數量，以及 `code_format`，其中 `b32-split-4` 是唯一值。權限提升必須透過重新使用密碼進行身分認證，因此被盜會話不能自行生成程式碼；如果沒有身分認證，請求將以 `403` 失敗。詳見 [賬戶安全](/zh-TW/modules/account/security)。

明文程式碼只會返回一次。它們在儲存之前會像其他金鑰一樣進行雜湊處理。生成新的一組會使之前的程式碼失效。[恢復程式碼](/zh-TW/modules/trident/recovery-codes)介紹了它們的使用方法。

<span id="federated" />

### 聯合

憑據模型有一種變體記錄，它指向外部身分提供者，而不是儲存金鑰，攜帶 `provider_id` 和 `provider_type`。在 0.10.0 中沒有建立該記錄的操作。從 LDAP 提供者引入的使用者會獲得一個 `password` 憑據，其儲存的金鑰為字面值 `federated`，這告知登入流程應檢查密碼與目錄而非資料庫匹配。透過例如 GitHub 的代理提供者登入的使用者根本沒有憑據：賬戶透過連結行與提供者關聯。提供者透過 [Abyss](/zh-TW/modules/abyss/overview) 模組進行管理。

<span id="temporary-credentials" />

## 臨時憑據

憑據可以被標記為臨時。這幾乎總是密碼，並且會觸發 `update_password` 所需的操作：使用者必須在獲得完整存取權限之前設定一個永久密碼。

<span id="credential-lifecycle" />

## 憑據生命週期

使用者通常最終會擁有一個密碼，一旦設定了 MFA 就會有一個 TOTP 憑據，如果他們請求過的話，還會有一組恢復碼，以及可能一個或多個 WebAuthn 金鑰。

管理員可以透過管理控制檯重置密碼並刪除任何憑據。使用者透過賬戶控制檯管理自己的憑據，該控制檯在進行敏感更改之前會要求他們重新進行身分認證。
