# Resources

Each section shows an example, the attributes worth knowing about and the import command. The [provider repository](https://github.com/ferriskey/terraform-provider-ferriskey/tree/main/docs) has the full schema of every resource.

An attribute marked **replaces** cannot be changed in place: changing it destroys the object and creates a new one, with a new UUID. For a user or a client, that also drops what hangs off the old one, such as credentials, sessions and role assignments.

## ferriskey_realm

```hcl
resource "ferriskey_realm" "acme" {
  name = "acme"
}
```

| Attribute | Description |
|---|---|
| `name` | Realm name. Renamed in place, but every URL and issuer of the realm changes with it |
| `realm_id` | UUID, read-only |
| `settings` | Read-only copy of the realm settings. Manage them with `ferriskey_realm_settings` |

Destroying the resource deletes the realm and everything in it. The `master` realm cannot be deleted, so do not manage it with this resource: read it with the [`ferriskey_realm` data source](/en/terraform/data-sources#ferriskey_realm).

```bash
terraform import ferriskey_realm.acme acme
```

## ferriskey_realm_settings

```hcl
resource "ferriskey_realm_settings" "acme" {
  realm                     = ferriskey_realm.acme.name
  access_token_lifetime     = 600
  refresh_token_lifetime    = 43200
  user_registration_enabled = true
  forgot_password_enabled   = true
  passkey_enabled           = true
}
```

Manages the [realm settings](/en/discover/core-concepts/realms#realm-settings): token lifetimes, `default_signing_algorithm`, registration, forgotten password, remember me, magic links, passkeys, email verification and `compass_enabled`. Lifetimes are in seconds, `email_verification_ttl_hours` in hours and `magic_link_ttl` in minutes.

An update is a partial merge, like the API: a setting you leave out keeps its current value, it is not reset to the default. Destroying the resource stops managing the settings and changes nothing on the server.

`require_mfa`, `login_aliases`, the lockout, consent, locale and branding settings are not in the resource yet. Set them in the console or with `PUT /realms/{realm_name}/settings`.

```bash
terraform import ferriskey_realm_settings.acme acme
```

## ferriskey_client

```hcl
resource "ferriskey_client" "web" {
  realm         = ferriskey_realm.acme.name
  client_id     = "acme-web"
  name          = "Acme Web App"
  client_type   = "confidential"
  redirect_uris = [
    "https://app.acme.example/callback",
    "https://app.acme.example/silent-renew",
  ]
  access_token_lifetime = 300
}

resource "ferriskey_client" "spa" {
  realm                        = ferriskey_realm.acme.name
  client_id                    = "acme-spa"
  name                         = "Acme SPA"
  client_type                  = "public"
  public_client                = true
  direct_access_grants_enabled = false
  redirect_uris                = ["https://spa.acme.example/callback"]
}
```

| Attribute | Description |
|---|---|
| `client_id` | The `client_id` applications send |
| `client_type` | `confidential`, `public` or `system`. **Replaces** |
| `public_client` | No secret, PKCE carries the protection. **Replaces** |
| `service_account_enabled` | Allows the `client_credentials` grant. **Replaces** |
| `direct_access_grants_enabled` | Allows the deprecated password grant |
| `redirect_uris` | A set, so order does not matter. Leave it out to leave the client's redirect URIs alone, set `[]` to remove them all. See [redirect URIs](/en/discover/core-concepts/clients#redirect-uris) |
| `access_token_lifetime`, `refresh_token_lifetime`, `id_token_lifetime`, `temporary_token_lifetime` | Per-client overrides, in seconds. The realm value applies when unset |
| `secret` | Generated by the server, read-only and sensitive. Stored in the state |
| `service_account_user_id` | The service account user, when `service_account_enabled` is on. Give it roles with `ferriskey_user_role` |

The other [client properties](/en/discover/core-concepts/clients#client-properties), such as `require_pkce`, `token_exchange_enabled`, `consent_required`, back-channel logout, post-logout redirects and web origins, are not in the resource yet. A client created by the provider gets the server defaults for them.

```bash
terraform import ferriskey_client.web acme/3a8c6128-1111-2222-3333-444455556666
```

## ferriskey_user

```hcl
resource "ferriskey_user" "alice" {
  realm            = ferriskey_realm.acme.name
  username         = "alice"
  email            = "alice@acme.example"
  email_verified   = true
  firstname        = "Alice"
  lastname         = "Liddell"
  required_actions = ["update_password"]
}
```

| Attribute | Description |
|---|---|
| `username` | **Replaces** |
| `email` | Once set, it can be changed but not cleared: removing it from the configuration leaves the server value |
| `email_verified` | `false` by default |
| `enabled` | `true` by default |
| `required_actions` | `verify_email`, `update_password`, `configure_passkey`. See [required actions](/en/discover/core-concepts/users#required-actions) |
| `user_uuid` | UUID, read-only. Use it in `ferriskey_user_role` and `ferriskey_organization_member` |

The resource sets no password and no credential. Set them in the console, with the API, or let the user sign in another way, such as a magic link or an identity provider.

Leave `configure_otp` out of `required_actions`. FerrisKey works it out at each sign-in from the realm and the user's roles and never stores it, so Terraform would plan to add it on every run.

The user removes `verify_email` and `update_password` from their account by completing them. Terraform then plans to add them back. Add `lifecycle { ignore_changes = [required_actions] }` when the actions are set once at creation.

```bash
terraform import ferriskey_user.alice acme/9f1c0e2a-aaaa-bbbb-cccc-ddddeeeeffff
```

## ferriskey_role

```hcl
resource "ferriskey_role" "support" {
  realm       = ferriskey_realm.acme.name
  name        = "support"
  description = "Read-only support staff"
  permissions = ["view_users", "query_users", "view_clients"]
}
```

`permissions` takes the snake_case names of the [permissions reference](/en/discover/core-concepts/roles#permissions-reference), and replaces the whole set on update. `realm` **replaces**. The resource manages realm roles only: `client_id` is read-only.

A name that matches no permission is dropped silently when the provider's account holds `manage_realm`, and refused with a 403 otherwise. In the first case, the server never stores it, so every `plan` shows it again. Check the names when a role keeps showing a change.

```bash
terraform import ferriskey_role.support acme/4b2d7f90-1111-2222-3333-444455556666
```

## ferriskey_user_role

```hcl
resource "ferriskey_user_role" "alice_support" {
  realm   = ferriskey_realm.acme.name
  user_id = ferriskey_user.alice.user_uuid
  role_id = ferriskey_role.support.role_uuid
}
```

Assigns a realm role to a user, or to a client's service account through `service_account_user_id`. It is a link with no attributes of its own: every change replaces it. Destroying it removes the assignment, not the user or the role.

```bash
terraform import ferriskey_user_role.alice_support acme/USER_UUID/ROLE_UUID
```

## ferriskey_organization

```hcl
resource "ferriskey_organization" "globex" {
  realm       = ferriskey_realm.acme.name
  name        = "Globex"
  alias       = "globex"
  description = "Globex Corporation tenant"
  domain      = "globex.example"
}
```

`alias` is the stable, URL-safe identifier of the organization within the realm. `enabled` is `true` by default, `redirect_url` is optional, and `realm` **replaces**.

```bash
terraform import ferriskey_organization.globex acme/7c3e9a14-1111-2222-3333-444455556666
```

## ferriskey_organization_member

```hcl
resource "ferriskey_organization_member" "alice_globex" {
  realm           = ferriskey_realm.acme.name
  organization_id = ferriskey_organization.globex.organization_uuid
  user_id         = ferriskey_user.alice.user_uuid
}
```

Adds a user to an organization. Like `ferriskey_user_role`, it is a link and every change replaces it.

```bash
terraform import ferriskey_organization_member.alice_globex acme/ORG_UUID/USER_UUID
```

## ferriskey_password_policy

```hcl
resource "ferriskey_password_policy" "acme" {
  realm             = ferriskey_realm.acme.name
  min_length        = 14
  require_uppercase = true
  require_lowercase = true
  require_number    = true
  require_special   = true
  max_age_days      = 365
}
```

Manages the realm's [password policy](/en/discover/core-concepts/password-policy). Leave `max_age_days` unset for passwords that never expire. A realm always has a policy, so destroying the resource stops managing it and leaves the policy as it is.

```bash
terraform import ferriskey_password_policy.acme acme
```

## ferriskey_smtp_config

```hcl
resource "ferriskey_smtp_config" "acme" {
  realm      = ferriskey_realm.acme.name
  host       = "smtp.example.com"
  port       = 587
  username   = "mailer"
  password   = var.smtp_password
  from_email = "no-reply@acme.example"
  from_name  = "Acme"
  encryption = "tls"
}
```

Manages the realm's SMTP settings, described in the [email guide](/en/discover/guides/email). All attributes are required. `encryption` is `tls`, `ssl` or `none`.

The API never returns `password`. Terraform keeps the value from the configuration, so a password changed in the console is not seen as drift, and after an import the password has to be set in the configuration before the next `apply`. Destroying the resource deletes the realm's SMTP configuration.

```bash
terraform import ferriskey_smtp_config.acme acme
```

## ferriskey_identity_provider

```hcl
resource "ferriskey_identity_provider" "google" {
  realm        = ferriskey_realm.acme.name
  alias        = "google"
  provider_id  = "oidc"
  display_name = "Google"

  config = {
    clientId     = var.google_client_id
    clientSecret = var.google_client_secret
  }
}
```

| Attribute | Description |
|---|---|
| `alias` | Unique within the realm. **Replaces** |
| `provider_id` | `oidc` or `saml`. **Replaces** |
| `config` | Provider-specific keys, such as `clientId`, `clientSecret` or `authorizationUrl`. Only the keys you set are managed: keys the server adds are ignored |
| `enabled` | `true` by default |
| `trust_email`, `link_only`, `store_token`, `add_read_token_role_on_create` | Booleans, server default when unset |
| `first_broker_login_flow_alias`, `post_broker_login_flow_alias` | Flow aliases |

The import ID uses the alias, not a UUID:

```bash
terraform import ferriskey_identity_provider.google acme/google
```
