# 品牌、门户和组织策略

CIAM 系统必须接受这样一个事实：一个产品服务于许多客户，而这些客户希望获得不同的体验。Acme Corp 员工的登录页面不应与 Globex Inc. 的完全相同。具有严格安全策略的 B2B 客户可能要求每个人都使用多因素认证；而免费客户可能根本不在意。

有三个 CIAM 概念处理这个问题：品牌化、组织级策略和门户。

<span id="branding" />

## 品牌

品牌化是可见的层面。用户看到：

- 登录页面上的徽标、颜色和文本。
- 自定义域名（`login.acme.com` 而非 `login.your-product.com`）。
- 用于密码重置、魔法链接、邀请的主题电子邮件模板。
- 与客户匹配的网页图标和标签标题。

大多数 CIAM 平台允许每个租户覆盖基础主题。常用方法是提供默认主题，并允许域覆盖 CSS 变量和字符串槽位。

值得遵守的一条指南是：对用户在身份认证过程中看到的所有内容都进行品牌化，包括错误信息和邮件模板。半品牌化的流程会让用户感觉不完整，即使他们说不出原因。

<span id="org-level-policies" />

## 组织级策略

策略是适用于所有在此组织/身份域进行身份认证的人的规则，无论他们使用哪个应用程序。

常见策略：

- **必需的多因素认证 (MFA)**：TOTP、WebAuthn，或两者。
- **允许的登录方式**：如果必须使用 SSO，则禁用邮箱/密码登录。
- **会话期限**：金融客户为短期，休闲产品为长期。
- **密码规则**：长度、字符类别、泄露名单检查。
- **身份提供者 (IdP) 限制**：仅允许通过客户自己的 SAML/OIDC 提供商登录。
- **邮箱域声明**：任何使用 `@acme.com` 注册的人自动成为 Acme 组织的成员。
- **账户自我删除**：允许或不允许。

这些策略由授权服务器执行，而不是由应用程序执行。这就是关键所在：每个信任该服务器的应用程序都会自动继承该策略。

<span id="portals" />

## 门户

门户是面向用户（而非管理员）的 CIAM 特定用户界面：

- **账户门户**：用户在此管理其个人资料、会话、凭据、多因素认证和关联的社交账户。
- **组织管理员门户**：组织管理员在此管理其用户、邀请、SSO 设置和策略，_无需_访问平台的其他管理权限。

组织管理员门户是成熟 CIAM 的标志。它让您的客户自助管理用户，而无需向您提交工单。

<span id="the-b2b-vs-b2c-split" />

## B2B 与 B2C 的区分

CIAM 必须同时处理两者：

- **B2C**：与终端用户直接关系。自助注册、社交登录、品牌一致性。
- **B2B**：你的客户是公司。你在他们那边分配管理员，联合他们的企业身份提供商（IdP），遵守他们的安全策略。

实际系统通常两者兼具。一个B2C产品发展出企业客户，现在需要SAML + 每组织多因素认证 + SCIM配置。一个B2B平台增加“免费层”，现在需要自助注册 + 社交登录 + 每用户升级。

CIAM平台的工作是让这种过渡成本低。

<span id="a-mental-model" />

## 一个思维模型

把CIAM想成是白标连锁酒店。

- 连锁酒店（你的产品）拥有建筑、管道、安保。
- 每家酒店（每个租户）装饰大堂、选择着装规范、设定入住规则。
- 客人（终端用户）看到的是酒店，而不是连锁品牌。
- 连锁酒店仍然在所有酒店中执行消防规范和结构完整性检查。这是你的安全基线。

## 在 FerrisKey 中

FerrisKey 使用身份域模型 CIAM。每个身份域都是一个独立的租户，拥有自己的用户、客户端、策略、品牌和身份提供者。多租户功能是内建于数据模型中的，而不是事后加上的。
