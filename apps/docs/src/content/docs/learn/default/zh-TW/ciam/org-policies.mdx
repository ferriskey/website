# 品牌、門戶和組織策略

CIAM 系統必須接受這樣一個事實：一個產品服務於許多客戶，而這些客戶希望獲得不同的體驗。Acme Corp 員工的登入頁面不應與 Globex Inc. 的完全相同。具有嚴格安全策略的 B2B 客戶可能要求每個人都使用多因素認證；而免費客戶可能根本不在意。

有三個 CIAM 概念處理這個問題：品牌化、組織級策略和門戶。

<span id="branding" />

## 品牌

品牌化是可見的層面。使用者看到：

- 登入頁面上的徽標、顏色和文字。
- 自定義域名（`login.acme.com` 而非 `login.your-product.com`）。
- 用於密碼重置、魔法連結、邀請的主題電子郵件模板。
- 與客戶匹配的網頁圖示和標籤標題。

大多數 CIAM 平臺允許每個租戶覆蓋基礎主題。常用方法是提供預設主題，並允許域覆蓋 CSS 變數和字串槽位。

值得遵守的一條指南是：對使用者在身分認證過程中看到的所有內容都進行品牌化，包括錯誤資訊和郵件模板。半品牌化的流程會讓使用者感覺不完整，即使他們說不出原因。

## 組織級策略

策略是適用於所有在此組織/身分域進行身分認證的人的規則，無論他們使用哪個應用程式。

常見策略：

- **必需的多因素認證 (MFA)**：TOTP、WebAuthn，或兩者。
- **允許的登入方式**：如果必須使用 SSO，則禁用郵箱/密碼登入。
- **會話期限**：金融客戶為短期，休閒產品為長期。
- **密碼規則**：長度、字元類別、洩露名單檢查。
- **身分提供者 (IdP) 限制**：僅允許透過客戶自己的 SAML/OIDC 提供商登入。
- **郵箱域宣告**：任何使用 `@acme.com` 註冊的人自動成為 Acme 組織的成員。
- **賬戶自我刪除**：允許或不允許。

這些策略由授權伺服器執行，而不是由應用程式執行。這就是關鍵所在：每個信任該伺服器的應用程式都會自動繼承該策略。

## 門戶

門戶是面向使用者（而非管理員）的 CIAM 特定使用者介面：

- **賬戶門戶**：使用者在此管理其個人資料、會話、憑據、多因素認證和關聯的社交賬戶。
- **組織管理員門戶**：組織管理員在此管理其使用者、邀請、SSO 設定和策略，_無需_存取平臺的其他管理權限。

組織管理員門戶是成熟 CIAM 的標誌。它讓您的客戶自助管理使用者，而無需向您提交工單。

<span id="the-b2b-vs-b2c-split" />

## B2B 與 B2C 的區分

CIAM 必須同時處理兩者：

- **B2C**：與終端使用者直接關係。自助註冊、社交登入、品牌一致性。
- **B2B**：你的客戶是公司。你在他們那邊分配管理員，聯合他們的企業身分提供商（IdP），遵守他們的安全策略。

實際系統通常兩者兼具。一個B2C產品發展出企業客戶，現在需要SAML + 每組織多因素認證 + SCIM配置。一個B2B平臺增加“免費層”，現在需要自助註冊 + 社交登入 + 每使用者升級。

CIAM平臺的工作是讓這種過渡成本低。

<span id="a-mental-model" />

## 一個思維模型

把CIAM想成是白標連鎖酒店。

- 連鎖酒店（你的產品）擁有建築、管道、安保。
- 每家酒店（每個租戶）裝飾大堂、選擇著裝規範、設定入住規則。
- 客人（終端使用者）看到的是酒店，而不是連鎖品牌。
- 連鎖酒店仍然在所有酒店中執行消防規範和結構完整性檢查。這是你的安全基線。

## 在 FerrisKey 中

FerrisKey 使用身分域模型 CIAM。每個身分域都是一個獨立的租戶，擁有自己的使用者、客戶端、策略、品牌和身分提供者。多租戶功能是內建於資料模型中的，而不是事後加上的。
