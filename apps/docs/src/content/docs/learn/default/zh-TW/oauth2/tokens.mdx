# 存取權杖和重新整理權杖

成功的 OAuth2 流程返回的 JSON 資料大致如下所示：

```json
{
  "access_token": "eyJhbGciOi...",
  "token_type": "Bearer",
  "expires_in": 300,
  "refresh_token": "8xLOxBtZp8...",
  "scope": "openid profile email"
}
```

信封裡拿出兩張紙，一張是存取權杖，一張是重新整理權杖。它們的作用非常不同，但人們常常會混淆。

<span id="access-token" />

## 存取權杖

存取權杖就像代客鑰匙。客戶端向 API 出示它，以證明“我有權代表使用者執行此操作”。

你將它附加到 `Authorization` 頭的 API 呼叫中：

```http
GET /api/orders
Authorization: Bearer eyJhbGciOi...
```

<span id="properties" />

### 屬性

- 短期有效。幾分鐘，而不是幾小時。五分鐘是一個健康的預設值。
- 有作用域的。攜帶使用者（或管理員）授予的`scope`。API 使用作用域來決定允許什麼。
- 持有人。持有權杖的人可以像用現金一樣使用它。把它當成現金對待：如果可以的話，不要記錄它，不要放在網址裡，也不要把它存到`localStorage`裡。

<span id="why-so-short-lived" />

### 為什麼會持續這麼短暫？

如果存取權杖洩露，攻擊者會一直擁有存取權限直到其過期。短暫的生命週期會讓“永遠”變成“幾分鐘”。代價是：客戶端需要某種方式無聲續簽權杖。這正是重新整理權杖的作用。

<span id="refresh-token" />

## 重新整理權杖

重新整理權杖是允許客戶端請求新的存取權杖而無需再次打擾使用者的收據。

```bash
curl -X POST .../token \
  -d "grant_type=refresh_token" \
  -d "refresh_token=••••••••" \
  -d "client_id=my-frontend"
```

<span id="properties-1" />

### 屬性

- 持續時間長。根據政策，時間從數小時到幾周不等。
- 單一用途。僅用於獲取新的存取權杖，絕不呼叫API。
- 敏感。洩露的重新整理權杖比洩露的存取權杖嚴重得多。它是可以續期的存取來源。請妥善儲存，最好每次使用時都進行輪換。

<span id="refresh-token-rotation" />

### 重新整理權杖輪換

現代授權伺服器會輪換重新整理權杖：每次重新整理請求都會返回一個新的重新整理權杖，並使舊的權杖失效。如果攻擊者竊取了權杖並使用它，合法客戶端的下一次重新整理將會失敗，並明確發出警告。這是盜用的明顯訊號。

<span id="opaque-tokens-vs-jwt" />

## 不透明權杖與 JWT

OAuth2 並未指定存取權杖的格式。存在兩種陣營。

<span id="opaque-tokens" />

### 不透明權杖

一個隨機字串。看起來像 `8xLOxBtZp8N3...`。本身不攜帶任何資訊。要知道它授予了什麼權限，資源伺服器必須呼叫授權伺服器的 introspection 端點：

```http
POST /protocol/openid-connect/token/introspect
Authorization: Basic ...
token=8xLOxBtZp8N3...
```

伺服器響應後設資料：作用域、過期時間、它所代表的使用者。

**優點：** 可以立即撤銷（只需在伺服器端刪除記錄）。不會有宣告洩露到日誌中。

**缺點：** 每次 API 呼叫可能都需要與認證伺服器往返一次。延遲更高，耦合更多。

<span id="jwt-tokens" />

### JWT 權杖

一個簽名的 JSON 文件。資源伺服器可以使用認證伺服器的公鑰在本地驗證它。無需網路呼叫。

```
header.payload.signature
```

**優點：** 無狀態，快速，可水平擴充套件。

**缺點：** 在過期前無法撤銷。解決方法是使用較短的有效期 + 緊急情況的拒絕列表。

有關格式詳情，請參見 [JWT 部分](/zh-TW/learn/jwt/overview)。

<span id="which-to-choose" />

### 該選擇哪種？

- 如果你的 API 是分散式的、對延遲敏感，並且可以接受較短的有效期，那麼選擇 JWT。
- 如果你需要即時撤銷或不希望宣告儲存在客戶端記憶體中，則不透明。

大多數現代IAM系統，包括FerrisKey，預設情況下為存取權杖頒發JWT。

<span id="id-token-a-related-but-different-thing" />

## ID權杖：相關但不同的東西

OIDC增加了第三個權杖：ID權杖。它_不是_用來呼叫API的。它存在的目的是告訴客戶端誰已登入。完整資訊請參見[ID權杖](/zh-TW/learn/oidc/id-token)。混淆存取權杖和ID權杖是OIDC中最常見的新手錯誤。它們不能互換使用。
