# 組織

組織是在身分域內的 B2B 分組層。一個身分域可以容納多個組織，一個使用者可以同時屬於多個組織，每個組織都有自定義的鍵值後設資料，成員可以被分配具有組織範圍的角色。這涵蓋了常見的多租戶 SaaS 模式：客戶是組織，使用者是成員。

<Callout variant="info" title="剛接觸 B2B 身分？">

關於面向客戶（B2B/CIAM）身分與員工 IAM 不同的概念背景，請參見 Learn 部分的 [什麼是 CIAM？](/zh-TW/learn/ciam/overview) 和 [品牌、門戶與組織策略](/zh-TW/learn/ciam/org-policies)。

</Callout>

<span id="why-organizations" />

## 為什麼需要組織？

Realm 在部署層面進行隔離，每個產品或每個環境一個 Realm。組織位於其下一層。它們讓你可以建模客戶的業務結構，而無需為每個客戶建立一個 Realm。

在以下情況下使用組織：

- 你的使用者屬於具有不同身分的客戶賬戶（公司名稱、計費方案、外部 ID）。
- 你需要列出給定使用者所屬的每個組織，或給定組織的每個成員。
- 你希望將任意後設資料附加到客戶賬戶（CRM ID、訂閱層級、功能標記）而無需擴充套件使用者模式。

當您需要完全的憑據隔離、不同的認證策略或每個租戶不同的權杖有效期時，請為每個租戶使用單獨的身分域。

<span id="organization-fields" />

## 組織欄位

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `id` | UUID v7 | 已生成 | 識別符號 |
| `realm_id` | UUID | 已生成 | 該組織所屬的身分域 |
| `name` | 字串（1 到 255） | 是 | 可讀標籤 |
| `alias` | 字串（1 到 255） | 是 | URL 安全識別符號：小寫 ASCII 字母、數字、`-` 和 `_`。每個身分域唯一 |
| `domain` | 字串（最多 255） | 不 | 電子郵件域名。已儲存並驗證，但尚未用於自動入職。請參閱下面的路線圖 |
| `redirect_url` | 字串 | 不 | 回撥 URL |
| `description` | 字串 | 不 | 自由文字描述 |
| `enabled` | 布林值 | 不 | 預設為 `true`。被禁用的組織會拒絕新成員加入 |
| `created_at` | 日期時間（UTC） | 已生成 | 建立時間戳 |
| `updated_at` | 日期時間（UTC） | 已生成 | 最後修改時間戳 |

<span id="endpoints" />

## 端點

| 方法 | 端點 | 說明 |
|---|---|---|
| `GET` | `/realms/{realm_name}/organizations` | 列出該身分域的所有組織 |
| `POST` | `/realms/{realm_name}/organizations` | 建立一個組織。回答 `201` |
| `GET` | `/realms/{realm_name}/organizations/{organization_id}` | 讀取一個組織 |
| `PUT` | `/realms/{realm_name}/organizations/{organization_id}` | 更新一個組織。您留空的欄位將保持其原有值 |
| `DELETE` | `/realms/{realm_name}/organizations/{organization_id}` | 刪除一個組織。答案 `204` |

刪除一個組織會刪除其屬性、成員關係及其組。使用者保持不變。

<span id="listing-organizations" />

### 列出組織

列表是分頁的，如 [API 列表](/zh-TW/discover/guides/api-listings) 所述。在共享引數之上，它會根據以下條件篩選：

| 引數 | 匹配 |
|---|---|
| `search` | 名稱、別名、域名或描述的不區分大小寫的子字串 |
| `name`, `alias`, `domain`, `description` | 該欄位的大小寫不敏感子字串 |
| `enabled` | `true`或`false` |
| `has_domain` | `true` 保留有域名的組織，`false` 保留沒有域名的組織 |
| `without_member` | 一個使用者 ID：保留該使用者未加入的組織 |
| `ids` | 最多 100 個組織 ID 的逗號分隔列表 |
| `created_from`, `created_to` | RFC 3339 日期時間，包括和不包括 |

`order_by` 接受 `name`、`alias`、`enabled`、`created_at`（預設）和 `updated_at`。

<span id="realm-scoping" />

## 身分域範圍

每個組織只屬於一個身分域。所有 API 端點都是按身分域劃分的：

```text
/realms/{realm_name}/organizations
```

使用者及其加入的組織必須在同一身分域。跨身分域的成員資格會被拒絕。

`alias` 在身分域內必須是唯一的。使用已被佔用的別名建立或更新組織會返回 400，並給出原因 `already_exists`。

<span id="the-enabled-flag" />

## `enabled` 標誌

設定 `enabled: false` 會凍結成員新增：`POST /members` 開始拒絕請求。現有成員保持不變。這是暫停客戶而不刪除組織或清空其內容的方法。

<span id="permissions" />

## 權限

組織有它們自己的權限，`view_organizations` 和 `manage_organizations`，而 `manage_realm` 在任一權限下都被接受。使用者權限 `manage_users` 和 `view_users` 不授予存取組織的權限，因為管理身分域的使用者與管理其組織是不同的權限。

| 操作 | 所需權限 |
|---|---|
| 列出和讀取組織、成員、成員角色、組、組成員、組角色和屬性。列出使用者所屬的組織 | `view_organizations`, `manage_organizations` 或 `manage_realm` |
| 建立、更新和刪除組織。新增和移除成員。分配和撤銷角色。建立、更新和刪除組。更改屬性 | `manage_organizations`或`manage_realm` |

僅持有 `view_organizations` 的管理員可以瀏覽組織但不能更改其中的內容。

<Callout variant="info" title="路線圖">

仍然缺少：

- 基於域的自動入職。`domain` 欄位已儲存並驗證，但還沒有根據使用者的電子郵件域將其分配到組織。
- 組織策略。強制單點登入、域匹配規則和組織級身分認證策略尚未提供。
- 軟刪除。刪除是永久性的，沒有歸檔或恢復功能。

</Callout>

<span id="organizations-or-separate-realms" />

## 組織還是單獨的身分域？

| 場景 | 推薦 |
|---|---|
| B2B SaaS，客戶共享身分認證策略 | 一個身分域內的組織 |
| 客戶需要完全不同的權杖有效期或身分提供商聯合 | 每個客戶單獨的身分域 |
| 內部多團隊產品 | 一個身分域內的組織 |
| 受監管的多租戶隔離（資料駐留） | 單獨的身分域 |
