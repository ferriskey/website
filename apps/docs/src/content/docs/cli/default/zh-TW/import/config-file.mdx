# 從檔案匯入

`--from config` 從 FerrisKey 原生描述檔案匯入一個身分域。格式來自副檔名：`.yaml`、`.yml` 或 `.toml`。不涉及外部系統。

```bash
ferris-ctl realm import --from config --file realm.yaml
```

預覽但不寫入任何內容：

```bash
ferris-ctl realm import --from config --file realm.yaml --dry-run -o yaml
```

<span id="format" />

## 格式

描述包含一個 `name`，以及可選的 `settings`、`roles`、`clients` 和 `users` 部分。ferriskey-cli 倉庫在 [`examples/realm.yaml`](https://github.com/ferriskey/ferriskey-cli/blob/main/examples/realm.yaml) 提供了一個起點。

```yaml title="realm.yaml"
name: acme

settings:
  access_token_lifetime: 300
  refresh_token_lifetime: 1800
  user_registration_enabled: true
  forgot_password_enabled: true

roles:
  - name: admin
    description: Realm administrators
    permissions:
      - manage_realm
      - manage_users
  - name: viewer
    description: Read-only access
    permissions:
      - view_users
      - view_clients

clients:
  - client_id: web-app
    name: Web Application
    client_type: public
    public_client: true
    redirect_uris:
      - https://app.acme.test/callback
      - https://app.acme.test/*
  - client_id: backend
    name: Backend Service
    client_type: confidential
    service_account_enabled: true
    direct_access_grants_enabled: true
    roles:
      - name: service-reader
        description: Service-scoped read role

users:
  - username: alice
    email: alice@acme.test
    firstname: Alice
    lastname: Doe
    email_verified: true
    roles:
      - admin
  - username: bob
    email: bob@acme.test
    roles:
      - viewer
```

相同的鍵在 TOML 中也適用。包含列表的章節會變成表格陣列：

```toml title="realm.toml"
name = "acme"

[settings]
access_token_lifetime = 300
user_registration_enabled = true

[[roles]]
name = "admin"
description = "Realm administrators"
permissions = ["manage_realm"]

[[clients]]
client_id = "web-app"
client_type = "public"
public_client = true
redirect_uris = ["https://app.acme.test/callback"]

[[clients.roles]]
name = "reader"

[[users]]
username = "alice"
email = "alice@acme.test"
roles = ["admin", "web-app:reader"]
```

<Callout variant="warning" title="拼寫錯誤的鍵不是錯誤">

匯入器會忽略它不認識的鍵，不會發出警告。拼寫錯誤或來自其他工具的鍵會保留預設值。透過 `--dry-run -o yaml` 執行該檔案並讀取結果：它會列印匯入器理解的每個欄位及其值。

</Callout>

<span id="settings" />

## 設定

每個設定都是可選的。你省略的任何內容都會保持 FerrisKey 的預設值。設定會在每次執行時重新傳送，因此每次都會覆蓋當前身分域的值。

| 欄位 | 說明 |
|-------|-------------|
| `default_signing_algorithm` | 權杖簽名演算法 |
| `access_token_lifetime` | 存取權杖有效期（秒） |
| `refresh_token_lifetime` | 重新整理權杖有效期（秒） |
| `id_token_lifetime` | ID 權杖有效期（秒） |
| `temporary_token_lifetime` | 臨時權杖有效期（秒） |
| `user_registration_enabled` | 允許自助註冊 |
| `forgot_password_enabled` | 啟用忘記密碼流程 |
| `remember_me_enabled` | 啟用“記住我”功能 |
| `magic_link_enabled` / `magic_link_ttl` | 魔法連結登入及其有效期 |
| `passkey_enabled` | 啟用通行金鑰 |
| `compass_enabled` | 啟用 Compass 模組 |
| `email_verification_enabled` | 要求電子郵件驗證 |
| `email_verification_ttl_hours` | 電子郵件驗證連結有效期（小時） |

<span id="roles" />

## 角色

| 欄位 | 預設 | 說明 |
|-------|---------|-------------|
| `name` | 必填 | 角色名稱 |
| `description` | 無 | 自由文字描述 |
| `permissions` | `[]` | 權限名稱，使用下劃線命名法 |

權限使用[權限參考](/zh-TW/discover/core-concepts/roles#permissions-reference)中的名稱，所以是 `manage_realm`，而不是 `ManageRealm`，也不是 `realm:manage`。

執行匯入的身分只能授予它持有的權限。沒有 `manage_realm`，如果一個角色列出了身分沒有的權限，或者名稱 FerrisKey 不知道，該請求會以 403 `cannot grant a permission you do not hold` 拒絕，且匯入停止。有了 `manage_realm`，FerrisKey 不識別的名稱會被接受並丟棄，因此角色建立時的權限比檔案列出的少。

<span id="clients" />

## 客戶端

| 欄位 | 預設 | 說明 |
|-------|---------|-------------|
| `client_id` | 必填 | 客戶端識別符號 |
| `name` | 無 | 顯示名稱 |
| `client_type` | `public` | `public`、`confidential` 或 `system` |
| `protocol` | `openid-connect` | 客戶端使用的協議 |
| `enabled` | `true` | 客戶端是否可以使用 |
| `public_client` | `false` | 公共客戶端，無密碼 |
| `service_account_enabled` | `false` | 建立關聯的服務賬戶使用者 |
| `direct_access_grants_enabled` | `false` | 允許密碼授權 |
| `device_authorization_grant_enabled` | `false` | 允許裝置授權授予，這是 `ferris-ctl login` 所需的 |
| `redirect_uris` | `[]` | 允許的重定向 URI |
| `post_logout_redirect_uris` | `[]` | 允許的登出後重定向 URI |
| `web_origins` | `[]` | 允許在此客戶端的域範圍路由上使用的瀏覽器來源 |
| `require_pkce` | 繼承 | 在授權碼流程中要求使用 PKCE |
| `access_token_lifetime` | 繼承 | 覆蓋域存取權杖的 TTL（以秒為單位） |
| `refresh_token_lifetime` | 繼承 | 覆蓋域重新整理權杖的 TTL |
| `id_token_lifetime` | 繼承 | 覆蓋域 ID 權杖的 TTL |
| `temporary_token_lifetime` | 繼承 | 覆蓋域臨時權杖的 TTL |
| `roles` | `[]` | 針對該客戶端的角色，與域角色形狀相同 |

已存在的客戶端不會被修改，除了 `require_pkce` 和生命週期，它們在每次執行時都會再次傳送。缺失的重定向 URI、網頁來源和角色會被新增。報告列出了每個機密客戶端的金鑰；見 [匯入報告](/zh-TW/cli/import/overview#the-import-report)。

<span id="users" />

## 使用者

| 欄位 | 預設 | 說明 |
|-------|---------|-------------|
| `username` | 必填 | 使用者名稱 |
| `id` | 無 | 使用此 UUID 建立使用者，而不是生成的 UUID |
| `email` | 無 | 電子郵件地址 |
| `firstname` | 無 | 名字 |
| `lastname` | 無 | 姓氏 |
| `email_verified` | 無 | 將電子郵件標記為已驗證 |
| `roles` | `[]` | 要分配的角色 |
| `credential` | 無 | 作為使用者密碼儲存的密碼雜湊，見下文 |

`roles` 中的一個普通名稱指的是身分域角色。給它加上客戶端 ID 字首以選擇限定於該客戶端的角色：

```yaml
users:
  - username: alice
    roles:
      - admin              # realm role
      - backend:service-reader   # role of the "backend" client
```

`client_id:role` 如果檔案中沒有任何客戶端定義，且客戶端本身也未持有，會停止匯入。一個與任何身分域角色都不匹配的普通名稱僅會生成警告，該分配會被跳過。

<span id="passwords" />

### 密碼

沒有 `credential` 的情況下，使用者會以無密碼狀態到達。可以在之後透過 [`ferris-ctl user set-password`](/zh-TW/cli/commands/user#user-set-password)、管理員控制檯或恢復流程設定密碼。要保留現有密碼，請給使用者它已經擁有的雜湊值：

```yaml
users:
  - username: alice
    credential:
      algorithm: bcrypt
      secret_data: "$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy"
      hash_iterations: 10
```

| 欄位 | 說明 |
|-------|-------------|
| `algorithm` | `bcrypt`、`argon2id`、`argon2i` 或 `argon2d` |
| `secret_data` | 作為來源儲存的雜湊值：一個 `$2a$`、`$2b$` 或 `$2y$` 的 bcrypt 字串，或 Argon2 PHC 字串 |
| `hash_iterations` | 雜湊內部寫入的成本：bcrypt 成本（4 到 14），或 Argon2 的時間成本 `t`。當兩者不一致時，伺服器會拒絕該雜湊 |

匯入會按原樣儲存雜湊，且從不標記為臨時。FerrisKey 在使用者首次登入時將其重新編碼為 Argon2id；[匯出與匯入](/zh-TW/discover/guides/portability#password-hashes) 解釋了具體方法。已經有密碼的使用者將保留原密碼。拒絕的雜湊會增加警告並計入 `passwords_failed`，匯入過程會繼續。

儲存密碼雜湊的檔案與其來源的密碼儲存一樣敏感。請勿將其納入版本控制。`--dry-run` 輸出會遮蔽雜湊，但檔案本身不會。

<span id="fixed-ids" />

### 固定的 id

使用 `id`，使用者將以該 UUID 建立，這確保指向該使用者的所有識別符號保持有效。如果伺服器以不同的 ID 建立使用者，或者該 ID 已屬於其他使用者，匯入將以錯誤停止。

<Callout variant="info" title="在 0.3.0 版本中不可用">

使用者上的 `credential` 和 `id` 欄位是在 0.3.0 版本之後出現的。在 0.3.0 版本中，它們會像任何未知鍵一樣被忽略。要使用它們，請從 [ferriskey-cli](https://github.com/ferriskey/ferriskey-cli) 的 `main` 分支構建。

</Callout>
