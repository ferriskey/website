# FerrisKey CLI

`ferris-ctl` 是 FerrisKey 的官方命令行界面。它与 FerrisKey REST API 通信，因此您可以通过终端管理身份域、OAuth2 客户端和用户，从描述文件、Keycloak、Zitadel 或 Supabase 导入身份域，并编写管理任务脚本。

<span id="what-you-can-do" />

## 您可以执行的操作

::::card-group{cols=2}
:::card{label="管理上下文" icon="lucide:server" href="/zh-CN/cli/commands/context"}
存储连接配置（URL、客户端、身份域）并在环境之间切换。
:::
:::card{label="登录" icon="lucide:log-in" href="/zh-CN/cli/commands/login"}
使用 OAuth 2.0 设备授权授予进行身份认证。不需要客户端密钥。
:::
:::card{label="管理资源" icon="lucide:box" href="/zh-CN/cli/commands/realm"}
创建和检查身份域、客户端和用户。
:::
:::card{label="导入身份域" icon="lucide:import" href="/zh-CN/cli/import/overview"}
从文件、实时 Keycloak、实时 Zitadel 或 Supabase 项目迁移身份域。
:::

<span id="install" />

## 安装

:::codegroup
```bash [Cargo]
cargo install ferris-ctl
```

```bash [From source]
git clone https://github.com/ferriskey/ferriskey-cli.git
cd ferriskey-cli
cargo build --release
# binary at target/release/ferris-ctl
```

```bash [Docker]
docker run --rm ghcr.io/ferriskey/ferris-ctl --help
```
:::

从源代码构建需要 Rust 1.88 或更高版本。工作区没有设置 `rust-version`，但代码使用了 let 链，该特性在 1.88 中已稳定。

<span id="pre-built-binaries" />

### 预构建的二进制文件

每个 [GitHub 发布](https://github.com/ferriskey/ferriskey-cli/releases) 都包含三个归档。解压 `ferris-ctl` 并将其放在您的 `PATH` 上。

| 平台 | 归档 |
|----------|---------|
| Linux x86_64 | `ferris-ctl-v0.3.0-x86_64-unknown-linux-gnu.tar.gz` |
| macOS，Apple Silicon | `ferris-ctl-v0.3.0-aarch64-apple-darwin.tar.gz` |
| Windows x86_64 | `ferris-ctl-v0.3.0-x86_64-pc-windows-msvc.zip` |

这些名称遵循 `ferris-ctl-<tag>-<target>`；上面的是 0.3.0 版本。在同一版本中，一个 `SHA256SUMS.txt` 文件列出了每个归档的校验和，因此您可以在运行之前检查下载内容。Intel Mac 或 ARM 上的 Linux 没有预构建的二进制文件：请使用 Cargo 或相应的容器镜像。

<span id="container-image" />

### 容器镜像

镜像 `ghcr.io/ferriskey/ferris-ctl` 是为 `linux/amd64` 和 `linux/arm64` 构建的，其入口点是 `ferris-ctl`。一个版本会发布标签 `X.Y.Z`、`X.Y` 和 `X`。标签 `latest` 会在每次推送到 `main` 后重建，因此它可能比上一个版本更新：当您需要发布的构建时，请固定 `X.Y.Z`。

该镜像以没有主目录的非特权用户身份运行。通过 `FERRISKEY_URL`、`FERRISKEY_CLIENT_ID`、`FERRISKEY_CLIENT_SECRET` 和 `FERRISKEY_REALM` 传递连接，而不要依赖上下文文件（参见 [认证](/zh-CN/cli/authentication#overriding-the-context)）。

候选发布版本（带有 `-rc` 的标签）作为 GitHub 预发行版和镜像发布，但不会发布到 crates.io。

验证安装：

```bash
ferris-ctl --help
```

<span id="how-it-works" />

## 工作原理

```text
CLI args → ferris-ctl → resolve context + credentials → FerrisKey REST API
                              ↑
                  config.toml / credentials.toml
```

每个调用 API 的命令按顺序解析三件事：

1. 连接位置：从活动 [上下文](/zh-CN/cli/commands/context) 获取服务器 URL，或者在提供 `--client-id` 时从 `--url` 获取。
2. 你的身份：已保存的 [登录](/zh-CN/cli/commands/login) 会话，或存储在上下文中的客户端凭据。
3. 要操作的域：您登录的域是上下文的 `realm`，除非您传递 `--realm`，否则命令会在同一个域上执行。

<span id="global-flags" />

## 全局标志

这些标志适用于每个命令，无论是在子命令名称之前还是之后。

| 标志 | 短格式 | 默认 | 环境变量 | 说明 |
|------|-------|---------|---------|-------------|
| `--context` | | 活动上下文 | | 使用这个存储的上下文代替活动上下文 |
| `--output` | `-o` | `table` | | 输出格式：`table`、`json` 或 `yaml` |
| `--url` | | | `FERRISKEY_URL` | FerrisKey 服务器 URL |
| `--client-id` | | | `FERRISKEY_CLIENT_ID` | 用于登录的 OAuth2 客户端 |
| `--client-secret` | | | `FERRISKEY_CLIENT_SECRET` | 该客户端的密钥 |
| `--realm` | | | `FERRISKEY_REALM` | 命令作用的域 |

连接标志不是按字段覆盖的。`--url` 和 `--client-id` 只有在一起设置时才生效：当两者都设置时，CLI 会根据标志建立连接，并忽略配置文件和 `--context`。[身份认证](/zh-CN/cli/authentication#overriding-the-context) 详细说明了确切规则，包括 `login` 不同之处。

`-o` 适用于除 `login`、`logout` 和 `client secret` 之外的每个命令，这些命令总是打印纯文本。
